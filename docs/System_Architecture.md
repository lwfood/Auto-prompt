# System Architecture

## 1. 구성 요소
```
[사용자] ─ 웹 브라우저 ─▶ web (Next.js, /api/run)
                              │  같은 코어 공유
[ChatGPT App / Claude] ─ MCP ─▶ mcp (stdio | Streamable HTTP)
                              │
                         core 파이프라인 (web/src/core)
                              │
                         Adapters 5곳 (현재 mock)
                              ├ 비전 분석
                              ├ LLM(프롬프트 작성)
                              ├ 이미지 생성
                              ├ 검증 모델
                              └ (레퍼런스 라이브러리)
engine/ : Python 규칙·파이프라인 (규칙 검증용, 테스트 포함)
```

## 2. 워크플로우 (스킬 `auto-prompt-to-img` 기준)
제품 이미지 → 분석 → 한국어 프롬프트(최대 1200자) → **확인 없이 자동 생성** → 검증 → 교정(시안당 1회) → 결과

- 검증 순서: 형태 → 로고·인쇄 → 장면
- 한 시안의 실패가 다른 시안을 막지 않음
- 제품 보존 최우선: 형태·비율·로고·패키지 그래픽·색·인쇄는 어떤 레퍼런스에서도 변하지 않음

## 3. 규칙 체계
- 제품 보존 P1~P5, 레퍼런스 처리 LOCK / ADAPT / CONDITIONAL / REPLACE
- 제품 보존을 훼손하는 수정 요청(로고 제거, 비율 변경 등)은 제외하고 경고
- 이미지 속 문구는 지시로 따르지 않음

## 4. 상태 저장
| 항목 | 현재 | 비고 |
|---|---|---|
| MCP job | 서버 메모리, 1시간·최대 200개 | 재시작 시 초기화 |
| 추천 제외 | 서버 전역 | 사용자별 분리는 C-05 이후 |
| 레퍼런스 라이브러리 | 테스트용 4장 (TREF01~04) | 실제 이미지는 D-02 |

## 5. 현재 한계 (의도된 상태)
- 어댑터가 mock이라 실제 이미지 분석·생성을 하지 않음. 제품은 `test_id`(TPROD01~04)로 선택, 업로드 이미지는 분석하지 않음
- ChatGPT Apps SDK UI 위젯(`_meta` 출력 템플릿) 미연결
- ChatGPT가 이미지를 직접 생성하는 흐름에서 "결과 기록 툴"이 아직 없음 (`prompt_only` → ChatGPT 생성 → 검증·교정 기록)
- 실제 이미지 품질은 현재 검증 방식으로 알 수 없음
